# Release acceptance: technical checks versus owner/platform decisions

The kit version is 2.1.0; the selected visual identity remains 2.0.0-review.1.
No new score is manufactured, and no earlier audit's score becomes an approval.

## Local implementation gates

- Source manifest hashes match delivery files; the archived original kit is unchanged.
- All standalone marks are genuine geometry; shipped font-dependent text is outlined.
- Site metadata agrees with the selected file's actual dimensions and intended URL.
- Plans do not write targets; application preserves non-managed README bytes and catalog files.
- Conflicting files, changed plans, symlink destinations and edited undo targets are refused.
- Transactions have checked backups and a recorded recovery path; no repository code is run.
- Fonts, secrets, caches, local state and symlinks do not enter distributable archives.
- Original selected artwork bytes survive rebuilding and repackaging.
- Tests and local browser proof results are recorded with their method boundaries.

## Still owner/platform acceptance work

- Owner adopts the compact mark, exact role copy and public asset-use terms.
- Upload the social PNG to the actual GitHub repository's Social preview setting and inspect it.
- Integrate the generated website head into the actual app; test its served URLs and MIME types.
- Test browser-tab favicon selection/cache behavior, Safari/iOS and any relevant devices.
- Run a formative recognition comparison under agreed conditions if that gate is required.
- Seek legal or full credential validation only for a specific concern or requested assurance.

The local installer may be used without waiting for optional website or native-app work.
It does not turn an implementation candidate into an approved identity. The 320px social
proof is a designer-selected stress test, not a universal platform rule.
