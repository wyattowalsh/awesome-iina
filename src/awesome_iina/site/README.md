# Browser catalog

A static, progressively enhanced view of `src/awesome_iina/catalog/catalog.yaml`. This is not a separate
registry, install service, or automatically promoted discovery feed.

Run `just site-build` and `just site-preview`, then open the printed loopback address.
The generated tree is `dist/site/`. Deploy **only that tree**, never the repository root.
The intended origin and project path come from the supplied brand deployment metadata;
no deployment was performed here. Use the build artifact to review before publishing.

The page is grouped by provenance, not dumped as one list. Exclusive sections are
IINA core, official plugins, IINA’s published `plugins.json` index, other native
plugins, companions, developer resources, media tooling, and historical entries.
Index listing is not first-party ownership. Featured names jump to the on-page
entry; the project heading still opens the project URL.

Search, category/type/status filters, theme (shadcn ModeToggle: Light / Dark /
System), visible counts, and shareable query state live in the Vite island under
`ui/` (React 19 + Tailwind v4 + shadcn Button, DropdownMenu, Sheet, Select,
Dialog, Input, Badge, Separator, Tooltip). Jinja still SSR every project row.
Empty sections, unmatched Start-here rows, and empty Contents items hide when
filters leave them with no matches. Every entry renders without JavaScript; theme,
filters, and the labels glossary need JS. Start here is a short featured list
(name + one-liner). Contents jumps to provenance sections with counts. Project rows
use list grammar: name, flags, description, and at most three tags. List icons come
from `static/icons.svg` (`currentColor`, 20px).

On viewports below 768px, Category / Type / Status open in a bottom Sheet; search
stays inline. Desktop keeps the filter bar inline above Start here.

Templates are autoescaped and unsafe project-link schemes are rejected. No analytics,
service worker, or remote JSON fetch. CSP is `default-src 'self'` with
`style-src 'self' 'unsafe-inline'` for Radix positioning. Relative asset paths support
GitHub Pages project hosting; kit canonical/Open Graph URLs name the intended host.

Derived Open Graph and social PNGs are rendered by `takumi-js` from
`ui/og/catalog-card.tsx` (`npm --prefix src/awesome_iina/site/ui run og`, also
part of `just site-ui-build`). Kit originals under `kit/assets/brand/` are not
rewritten. Generated bytes also land in gitignored `output/og/`.

Artwork is copied byte-for-byte from the supplied kit; `tokens.css` is generated
from the kit. Catalog CSS maps those `--brand-*` values onto shadcn-named aliases
(`--background`, `--foreground`, `--card`, `--primary`, `--primary-foreground`,
`--muted`, `--muted-foreground`, `--border`, `--ring`, `--radius`). Light theme
keeps `--brand-light-cyan`; dark theme keeps `--brand-cyan`. Theme uses the
official shadcn Vite ModeToggle (`Button` + `DropdownMenu` Light / Dark / System)
backed by `ThemeProvider` (`html.dark` / `html.light`), not a ToggleGroup or Dark
theme chip.
